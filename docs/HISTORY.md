## 1. 첫 빌드 — 2026-08-04

원래 작업지시서([`archive/BUILD-ORDER-v3.md`](archive/BUILD-ORDER-v3.md))의 Phase 0~5를 하루에 구현했습니다.

- **Phase 0** Next.js + Prisma 7(드라이버 어댑터) + Auth.js v5 로그인, 시드 계정
- **Phase 1** 권한·공개 범위, 총관리자 숨김/소프트 삭제
- **Phase 2** 업무 CRUD, 참여·완료, 코멘트, 하드 삭제(자식 끌어올리기)
- **Phase 3** 파생 트리, **읽는 시점에 계산하는 상속 공유**(조상을 거슬러 올라가며 판정), React Flow 캔버스
- **Phase 4** 전체 업무 뷰, 필터, 참여자별 우선순위, 상태 그룹 뷰
- **Phase 5** 공유 제외 토글 — 판정을 "조상 중 하나라도 허용"에서 **"가장 가까운 조상의 grant 우선"**으로 바꿨다. 전체 공유한 뒤 특정 가지만 빼려면 이 규칙이어야 한다.

같은 날: 관리자 로그인을 이메일 대신 아이디(`admin`)로도 받게 했고, 로고·파비콘·PWA 아이콘을 넣었습니다.

## 2. 디자인 시스템 정착 — 08-04 ~ 08-07

- **한글 폰트가 깨졌다.** Geist는 한글을 지원하지 않는다. 이후 Inter로 바꿀 때도 한 번 더 깨질 뻔해서, **폰트를 바꿀 때 한글 대체 폰트를 반드시 명시**하는 규칙이 생겼다.
- **shadcn base-luma 프리셋**으로 전환: 파란 강조색 → 검정, 납작한 테두리 → 그림자로 뜨는 카드. 아이콘을 **Tabler 하나로 통일**(lucide 제거).
- **Float-or-Flat 규칙**: 카드·대화창·팝오버처럼 다른 것을 담는 것은 그림자로 띄우고, 버튼·입력칸처럼 하나의 조작 도구는 평평하게 둔다. 헤어라인 테두리를 앱 전체에서 걷어냈다.
- 사용자별 **포인트 컬러** 설정. 밝은 색을 고르면 글자색을 자동으로 어둡게 바꿔 대비를 지킨다.
- 다크 모드가 정의만 되어 있고 실제로 켜지는 경로가 없었다 → 시스템 설정을 따르도록 연결.

## 3. 초기 기능 확장 — 08-06 ~ 08-11

- 알림을 누르면 해당 화면으로 바로 이동(`?task=`, 지금은 `?project=` 딥링크)
- 총관리자가 화면에서 계정을 발급 — "DB 직접 발급" 원칙은 유지하되 창구만 UI로
- 코멘트 멘션 알림, 대시보드 '오늘/이번주 마감', **매주 반복** 프로젝트, 필터 즐겨찾기
- **활동 기록(AuditLog)**: 되돌리기 어려운 조작(담당자 위임, 영구 삭제)만 남긴다. 대상이 지워져도 기록은 남아야 해서 외래키 없이 문자열로 보관한다.
- 파트너 색상: 파트너의 속성이라 하위 프로젝트에 따로 물려줄 필요가 없다.
- 생성·상세 화면 대개편: 태그·링크 모델·목표일 삭제, 우선순위 3단계, '종료' → '완료'
- 설정 화면 권한 분리, 계정 비활성화(로그인 차단 + 참여자 목록에서 제외), 이메일 정규화(trim + 소문자)
- **미확인 빨간 점**: 내가 관여한 프로젝트에 마지막으로 본 뒤 코멘트나 수정이 생기면 표시
- 폼 오류가 나도 창이 닫혀 입력이 사라지던 문제 → 성공했을 때만 닫도록 통일

## 4. 성능과 안정성 — 08-07 ~ 08-11, 08-24

실제로 배포해 보니 느리고 가끔 무너졌습니다. 원인은 대부분 코드가 아니라 배치와 연결이었습니다.

| 문제 | 원인 | 조치 |
|---|---|---|
| 연결이 자주 끊김 | 세션 풀러가 무료 플랜 연결 수(15)에 금방 닿음 | 앱은 **트랜잭션 풀러(6543)**, 마이그레이션은 **세션 연결(DIRECT_URL, 5432)**로 분리 |
| 대시보드 5~6초 | 서버 함수는 미국(iad1), DB는 서울. 왕복 1회 약 200ms × 화면당 14~25회 | **함수 리전을 서울(icn1)로 고정** → 5.9초가 0.16초로 |
| 데이터가 늘면 느려질 위험 | 외래키에 인덱스가 하나도 없어 전부 순차 스캔 | 조회 패턴에 맞춘 복합 인덱스. 2000건 실측으로 확인 |
| join 방식 선택 | 적을 땐 LATERAL JOIN이 빠르고, 많아지면 개별 쿼리가 1.8배 빠름 | **목록은 `relationLoadStrategy: "query"`**, 상세는 기본(join) |
| 로그인 상태에서만 대시보드 500 | 삭제된 계정의 세션이 살아 있었고, `update`가 없는 레코드에서 예외를 던짐 | JWT 콜백에서 계정 존재·활성 여부를 매 요청 확인. 부수 기록은 `updateMany` |
| DB가 몇 초 끊기면 전원 로그아웃 | 계정 조회 실패(장애)를 "계정 없음"으로 취급 | **장애와 "실제로 없음"을 구분.** 장애 중에는 세션을 유지 |
| DB 순간 끊김에 화면 전체가 오류 | Supabase 풀러가 가끔 DB를 못 찾음 | **연결 실패일 때만** 150ms, 500ms 간격으로 재시도. 쿼리가 서버에 닿은 뒤의 오류는 재시도하지 않는다(쓰기 중복 방지) |

이 외에 중복 조회 제거, N+1 쿼리 통합, 무거운 섹션 지연 로딩, 알림 점검 1시간 간격 제한 등을 했습니다.

## 5. 구조 전환 (D1~D4)과 화면 정비 (P1~P11) — 08-12 ~ 08-13

사용자가 결정한 4건을 반영한 가장 큰 변경입니다.

- **D1** 최상위를 파트너로, 그 아래를 프로젝트로 **코드와 DB까지 전부** 이름을 바꿨다. 테이블을 새로 만들지 않고 RENAME해서 데이터를 지켰다. (부작용: 옛 인덱스 이름이 남아 있어서 나중에 `Task` 모델을 만들 수 없었다 → 그래서 이름이 `TaskItem`이다.)
- **D2** 파트너 숨김 → 계정별 개인 설정
- **D3** 삭제 → 보관함 + 영구 삭제
- **D4** 참여자 역할에 **조회 전용(VIEWER)** 추가. 하위 프로젝트에도 상속된다.

이어진 P1~P11:
- 보기 이름 통일: 리스트 뷰 / 보드 뷰 / 워크플로우
- 대시보드 정렬(최근 활동순 등) — `lastActivityAt`을 모든 변경이 거치는 한 함수(`revalidateProjectViews`)에서 갱신해, 새 기능을 추가해도 빠뜨릴 수 없게 했다.
- 파트너 고정, 파트너 설정을 한 번에 저장, 색상 프리셋
- 전체 프로젝트 다중 필터·검색·정렬 — 2000건으로 먼저 측정했다(110~150ms). 메모리에서 걸러도 충분해서 쿼리 구조를 바꾸지 않았다.
- 보드 뷰: 완료 그룹 기본 접힘, **상태 배지를 눌러 상태 변경**(모바일에서는 드래그가 사실상 불가능하다)
- 워크플로우: 접기/펼치기, 더블클릭 이름 수정, 연결선 삭제
- 프로젝트 상세 907줄 파일을 4개 부품으로 분리, 인라인 수정, @멘션 자동완성

## 6. 구글 캘린더 연동 (G1~G5) — 08-18 ~ 08-21

회사 공용 구글 계정 하나를 총관리자가 연결합니다.

- 토큰은 **AES-256-GCM으로 암호화**해 저장(`GOOGLE_TOKEN_KEY`)
- 권한은 최소한으로 요청: 읽기 + 앱이 만든 캘린더에만 쓰기 → 이후 '일정 추가'를 위해 `calendar.events` 추가(기존 연결은 다시 연결해야 적용)
- 구글 일정을 캘린더 화면에 표시, 여러 날 일정은 이어진 막대로
- **공개 + 마감일 있는 프로젝트를 "AR_PM 업무" 캘린더로 내보내기.** 저장 응답이 끝난 뒤(`after()`) 동기화해서 구글이 느리거나 실패해도 저장은 막히지 않는다.
- 구글 일정 → 프로젝트 전환(중복 전환 방지)
- 일정 수정·삭제·드래그 이동, 시간 지정 일정
- 시간대: 서버가 UTC로 돌기 때문에 **UTC로 바꾸지 않고 한국 벽시계 문자열 + `Asia/Seoul`**로 넘긴다. 바꾸면 새벽 일정이 하루 밀린다.
- 동기화 캘린더의 일정은 직접 수정을 막았다. 다음 동기화 때 프로젝트 내용으로 덮여 수정이 사라진 것처럼 보인다.

## 7. 태스크·참여 체계·개인화 — 08-19 ~ 08-21

- **태스크(체크리스트)** 신설: 구글 Tasks처럼 프로젝트 안에서 누구나 추가·체크하는 할 일 목록. 하단 탭에 '태스크' 추가.
- **파트너 참여 신청**: 공개 파트너는 바로 참여, 비공개는 관리자 수락. 비공개 파트너를 미참여자 목록에 **노출할지(`discoverable`)** 고를 수 있다. 노출해도 카드만 보이고 내용은 수락 뒤에 열린다.
- 프로젝트 생성·참여는 **그 파트너에 직접 참여 중인 사람만**
- 파트너 이름 중복 금지('이름 (1)' 제안)
- 프로젝트 카드 개인 고정, 프로필 사진 등록

## 8. 보안 — 08-21

- **모든 테이블에 RLS(행 수준 보안) 활성화, 정책 없음 = 전부 거부.** Supabase가 공개 키(anon)에 기본으로 열어 둔 테이블 권한을 막기 위해서다. Prisma는 RLS를 우회하는 `postgres` 역할로 접속해 영향이 없다(실측). **새 테이블도 마이그레이션에서 반드시 켠다.**
- 사용자가 입력한 주소는 **http/https만** 링크로 만든다. 다른 스킴(`javascript:` 등)은 누른 사람의 브라우저에서 실행된다.

## 9. 채팅 — 08-21

- 파트너방(멤버는 파트너 멤버십을 그대로 따름) · 1:1방(두 사람당 하나, 총관리자에게도 비공개) · 단체방(총관리자만 생성)
- 멘션·태그는 리치 에디터 없이 **평문에 마커로 저장** — `@[이름](id)`, `/[프로젝트](id)`. 검색·수정이 그대로 동작하고 화면에서만 칩으로 그린다.
- 읽음 표시, '여기까지 읽음', 답장, 리액션, 검색, 수정·삭제(소프트 삭제 — 답장이 가리키는 원본이 사라지지 않게)
- **3초 폴링은 패널이 열려 있고 탭이 보일 때만.** 안읽음 뱃지는 타이머 대신 탭 복귀·패널 닫기 때만 다시 읽는다. 호출 수가 시계가 아니라 실제 사용에 비례하게.

## 10. 알림과 설치형 앱(PWA) — 08-31

- **푸시를 벨 알림 전체로 확장**(처음엔 채팅만). 알림 생성 방식이 자리마다 달라서 생성 함수는 그대로 두고 "만든 뒤 푸시 한 줄"을 붙였다.
- **알림이 가는 화면을 정하는 규칙을 한 곳으로**(`lib/notify.ts`) — 벨과 푸시가 같은 규칙을 쓴다. 파트너 관련 알림 3종이 눌러도 아무 데도 안 가던 버그가 이걸로 잡혔다.
- 마감 임박·지연, 캘린더 일정 추가·D-1, 파트너·프로젝트 초대, 멘션, 담당자·관리자 변경 알림
- **크론**(매일 11:00 KST, `vercel.json`): `CRON_SECRET`이 없으면 전부 거절한다 — 열어 두느니 안 도는 편이 낫다.
- PWA가 실제로 설치되지 않던 원인 두 가지: 아이콘이 512라고 적혀 있었지만 실제로는 2048×2049였고, **매니페스트가 로그인 화면으로 튕기고 있었다**(브라우저는 매니페스트를 인증 없이 받는다).
- 서비스 워커는 아무것도 캐시하지 않는다. 캐시하면 새 배포가 막힌다.

## 11. 협업 콘텐츠 — 08-25 ~ 09-08

- **참여 버그**: 카드에는 '참여하기'가 뜨는데 눌러도 안 되던 문제. 목록과 서버가 서로 다른 기준을 쓰고 있었다(서버는 상위에서 물려받은 권한까지 "이미 참여"로 봤다). 서버 기준을 목록에 맞췄고, 물려받은 권한 등급은 유지한다.
- 프로젝트의 소속 파트너 변경 — **하위 트리 전체(보관된 것 포함)가 함께 이동**한다. 상위-하위는 같은 파트너 안에서만 성립하기 때문이다.
- **공지사항**: 전체공지(로그인한 누구나 작성·수정·삭제)와 파트너 공지(그 파트너 참여자만). 한 테이블에 `partnerId` 유무로 구분한다.
- 프로젝트 완료 시 **남은 태스크도 완료할지** 묻는다. 완료된 프로젝트는 수정이 막혀서 미완 태스크를 손댈 수 없게 되기 때문이다. 완료로 가는 세 경로(상세 버튼, 상태 배지, 칸반 끌어놓기)가 모두 이 창을 거친다.
- 완료된 프로젝트는 빨간 점을 뗀다(완료 자체가 수정 시각을 올려 오히려 켜지고 있었다).
- 프로필 사진 직접 자르기(원형 가이드). **화면 미리보기와 저장의 계산을 한 파일(`lib/crop.ts`)에만** 둔다 — 어긋나면 "보이는 것과 다르게 잘리는" 버그가 된다.
- **다른 사람에게 프로필 사진이 안 보이던 문제**: "사진 없음" 응답을 하루 동안 캐시하고 있었다. 사진이 있는 사람과 바뀐 시각을 레이아웃에서 한 번 읽어 내려 주고, 주소에 버전을 붙였다.
- 코멘트·메모·공지의 **주소를 링크로**, 긴 글이 상자를 넘지 않게. 코멘트 멘션도 칩으로.
- 날짜 칸에 **연도가 여섯 자리로 들어가던 문제**: 브라우저가 그 값을 정상으로 보고 제출했다. 공용 입력칸에 2000~2099 범위를 걸고 서버에서도 다시 검사한다. 없는 날짜(2월 30일)도 거부한다.
- 파트너 **바로가기 링크 카드**
- **코멘트 모아보기**: 전체 / 멘션된 / 내가 작성한 / 내 프로젝트, 묶어보기·개별 보기. 볼 수 있는 범위는 프로젝트 목록 규칙을 그대로 따른다 — 규칙을 두 벌 두면 언젠가 어긋난다.

## 12. 내비게이션과 사용성 — 09-09 ~ 10-14

- **공용 상단 바**: 왼쪽 앱 아이콘(누르면 설정·로그아웃) + 제목, 오른쪽 화면별 동작 + 알림 종. 화면마다 따로 짜서 종 위치가 제각각이었다.
- **만들기 버튼을 목록 바로 위로**: 무엇이 만들어지는지는 대상 목록 옆에 있을 때 분명하다. 태스크 탭에도 '태스크 추가'를 새로 만들었다.
- 태스크 탭은 보드 뷰로 들어가고 줄마다 담당자를 표시
- 전체 프로젝트 상단을 검색창 + '필터' 버튼 둘로 줄이고, 켜진 조건만 알약으로 표시
- 상태 배지 3색, 파트너 설정 버튼을 이름 옆으로, 바로가기 카드 축소(이름만)
- 하단 탭: **홈 · 파트너 · 전체 프로젝트 · 태스크 · 코멘트 · 캘린더**
- **마지막 보기 기억**: 브라우저가 아니라 **계정에** 저장해 기기를 옮겨도 따라간다. 화면마다 기억할 것만 정했다(검색어·날짜는 기억하지 않는다). 주소에 적힌 값이 항상 우선이다.
- 캘린더 '완료 숨김', 코멘트 **Enter = 줄바꿈 / Ctrl+Enter = 등록**, **좌우 화살표로 하단 탭 이동**(글 쓰는 중·조합키·창이 떠 있을 때는 동작 안 함)
- 파트너 페이지에서 파트너 탭을 누르면 **파트너 목록이 바로 뜬다**(목록은 열 때만 조회)
