# 개발 규칙 — 같은 사고를 두 번 내지 않기 위해

여기 있는 규칙은 모두 **실제로 한 번 터진 것**입니다. 어기면 같은 일이 다시 납니다.
배경 이야기는 [`HISTORY.md`](HISTORY.md)에 있습니다.

---

## 0. 가장 먼저 알아야 할 것

- **개발 DB와 운영 DB가 같습니다.** 로컬 `.env`의 `DATABASE_URL`이 운영 Supabase를 가리킵니다.
  - 마이그레이션은 적용하는 순간 **운영에 반영**됩니다.
  - 테스트로 만든 데이터는 **실제 팀원 화면에 보입니다.** 만들었으면 반드시 지웁니다.
  - 일부 검사 스크립트(`check:chat`, `check:notice`, `check:partner-link`, `check:project-read`)는 운영 DB에 쓰고 지웁니다.
  - 기존 테이블을 바꾸는 마이그레이션은 **추가만** 합니다(컬럼 삭제·이름 변경은 배포 전 코드가 깨짐).
- **Next.js 16입니다.** 학습 데이터와 API가 다를 수 있으니 코드를 쓰기 전에 `node_modules/next/dist/docs/`를 확인합니다(`AGENTS.md`).
- **무료 플랜에서 돌아갑니다**(Vercel Hobby + Supabase Free). 병목은 CPU가 아니라 **호출 수**입니다. 화면 하나가 서버를 몇 번 부르는지를 항상 셉니다.

## 1. 데이터베이스

| 규칙 | 이유 |
|---|---|
| 새 테이블 마이그레이션에는 **`ALTER TABLE ... ENABLE ROW LEVEL SECURITY;`**를 반드시 넣는다 | 안 넣으면 Supabase 공개 키로 그 테이블을 읽고 쓸 수 있다. Prisma는 RLS를 우회하므로 앱 동작에는 영향이 없다. |
| 마이그레이션 SQL은 직접 쓰고, 적용 후 **dev 서버를 재시작**한다 | 오래 켜 둔 dev 서버는 새로 생성된 Prisma Client를 못 읽어 `prisma.새모델`이 `undefined`가 된다(두 번 겪음). |
| `upsert`의 `update: {}`로 시각을 갱신하려 하지 않는다. 읽음 시각 같은 값은 **명시적으로 넣는다** | `update`가 비어 있으면 Prisma가 UPDATE를 건너뛰어 `@updatedAt`이 안 바뀐다. 빨간 점이 영원히 안 꺼지는 버그가 났다. |
| 부수 기록(점검 시각 등)은 `update` 대신 **`updateMany`** | `update`는 레코드가 없으면 예외를 던진다. 대시보드 전체가 500이 됐다. |
| 목록 조회는 `relationLoadStrategy: "query"`, 단건 상세는 기본값(join) | 2000건 실측: 목록은 query가 1.8배, 상세는 join이 2.6배 빠르다. |
| 연결: 앱은 트랜잭션 풀러(6543), CLI는 `DIRECT_URL`(5432) | 세션 풀러는 무료 플랜 연결 수를 금방 다 쓴다. |
| 재시도는 **연결 실패일 때만** (`lib/prisma.ts`) | 쿼리가 서버에 닿은 뒤 재시도하면 쓰기가 중복될 수 있다. |
| 모델명은 `Task`를 쓸 수 없다(`TaskItem`) | D1 리네임 때 남은 옛 인덱스 이름(`Task_pkey`)과 충돌한다. |
| 프로젝트의 상위·하위는 **같은 파트너 안에서만** | 트리를 그렇게 가정하고 읽는다. 파트너를 옮길 때는 하위 트리(보관된 것 포함)를 통째로 옮긴다. `npm run check:tree`로 확인. |

## 2. 서버/클라이언트 경계

| 규칙 | 이유 |
|---|---|
| **클라이언트 컴포넌트가 가져오는 모듈에 prisma를 import하지 않는다.** 상수·순수 함수는 별도 파일로 뺀다 (예: `lib/comment-filters.ts`, `lib/view-prefs-config.ts`, `lib/priority.ts`) | Postgres 드라이버가 브라우저 번들에 끌려와 `Can't resolve 'dns'` 빌드 오류가 난다(두 번 겪음). |
| base-ui의 `render` / `trigger` prop에 넘기는 컴포넌트는 **`"use client"`**이고 **`{...props}`를 펼친다** | 서버 컴포넌트를 넘기면 이미 그려진 결과가 건너가 속성 병합이 안 된다. 버튼을 눌러도 창이 안 열리고 하이드레이션이 어긋났다. |
| 서버 액션의 오류 메시지를 화면에 그대로 띄우지 않는다. **고정된 한국어 문구**를 쓰거나 액션이 오류를 값으로 돌려준다 | 운영 빌드는 서버 오류 메시지를 숨기고 `Minified React error #441`로 바꾼다. |
| 렌더 중에 `Date.now()`를 부르지 않는다. 기준 시각이 필요하면 **서버 페이지에서 정해 prop으로** 넘긴다(`new Date().getTime()`, 예: 보관함 남은 날짜) | `react-hooks/purity` 린트 규칙. 브라우저에서 따로 재면 서버 렌더와 값이 갈려 하이드레이션이 어긋날 수 있다. |
| effect 안에서 동기적으로 `setState`하지 않는다 | `react-hooks/set-state-in-effect` 린트 규칙. "어느 키의 데이터인지"를 상태에 함께 담고 불일치를 로딩으로 본다 (`app/tasks/new-task-dialog.tsx`). URL과 입력칸 동기화는 렌더 중 상태 조정 패턴. |
| 변경 후 화면 갱신은 **`revalidateProjectViews()`** 한 곳을 거친다 (`lib/revalidate.ts`) | `lastActivityAt` 갱신과 구글 캘린더 동기화(`after()`)가 여기 붙어 있다. 우회하면 정렬과 동기화가 조용히 빠진다. |
| 외부 API 호출(구글, 푸시)은 **`after()`**로 응답 뒤에 | 외부가 느리거나 실패해도 저장은 막히지 않는다. |

## 3. 날짜와 시간

서버는 **UTC**, 사용자는 **한국 시간**입니다. 날짜 버그는 대부분 이 차이에서 납니다.

| 규칙 | 이유 |
|---|---|
| 화면에 찍는 시각은 **서버에서 `koreanStamp()`** (`lib/ui.ts`) | `toLocaleString("ko-KR")`은 Node와 브라우저가 "오후"/"PM"으로 갈려 하이드레이션이 깨진다. |
| "무슨 날인가"는 **`seoulDateKey()`**로 비교 (`lib/google/calendar.ts`) | 구글 종일 일정과 시간 지정 일정의 시작일이 서로 다른 기준으로 만들어진다. 시각 그대로 비교했다가 3건 중 0건이 잡혔다. |
| 구글로 보내는 시각은 UTC로 바꾸지 않고 **벽시계 문자열 + `Asia/Seoul`** | 바꾸면 새벽 일정이 하루 밀린다. |
| 날짜 입력은 **공용 `Input`**을 쓰고, 서버에서 **`parseDateInput()`** (`lib/date-input.ts`) | 브라우저 날짜 칸은 연도 6자리를 정상 값으로 제출한다. 공용 Input이 2000~2099 범위를 건다. 원시 `<input>`을 쓰면 다시 뚫린다. 없는 날짜(2/30)는 JS가 조용히 3/2로 굴린다. |

## 4. 보안

| 규칙 | 이유 |
|---|---|
| 사용자가 넣은 주소는 **http/https만** 링크로 (`normalizeLink`, `linkifyText`) | `javascript:` 주소는 누른 사람 브라우저에서 실행된다. 문자열을 HTML로 심지 않고 React 엘리먼트로 조립한다. |
| 새 경로를 로그인 검사(`proxy.ts`)에서 뺄 때는 **비밀이 아닌 것만** | PWA 매니페스트·서비스 워커·아이콘만 예외. 크론은 예외지만 **`CRON_SECRET`을 직접 확인하고, 키가 없으면 전부 거절**한다. |
| 세션 검증은 **장애와 "계정 없음"을 구분**한다 (`auth.ts`) | 둘을 같이 보면 DB가 몇 초 끊길 때 전원이 로그아웃된다. |
| 로그인 잠금은 **비밀번호 비교 전에** 확인하고, 실패 횟수는 **increment**로 센다 (`lib/login-throttle.ts`) | 잠긴 동안 맞는 비밀번호를 받아 주면 정답이 드러난다. 읽고-더해-쓰기는 동시 대입에서 횟수가 덜 세어진다. |
| 새 검색·모아보기 화면은 **기존 목록 함수로 볼 수 있는 범위를 정한다** (`app/actions/search.ts`) | 검색이 따로 권한을 판정하면 비공개 프로젝트가 결과로 샌다. |
| 구글 토큰은 암호화 저장 (`GOOGLE_TOKEN_KEY`) | 평문 저장 금지. |
| 비밀 값(`VAPID_PRIVATE_KEY`, `CRON_SECRET`, 토큰)은 채팅·이슈·커밋에 붙여넣지 않는다 | Vercel에는 Secret 타입으로 직접 등록한다. |

## 5. 권한과 공개 범위

- 판정 로직은 `lib/permissions.ts`(파트너), `lib/projects.ts`의 `getProjectAccess`(프로젝트)에 있습니다.
- 프로젝트 접근은 **읽는 시점에 계산**합니다. 저장된 "접근 가능 목록"은 없습니다. 가장 가까운 조상의 grant가 이깁니다.
- **목록 화면과 서버가 같은 기준을 써야 합니다.** 카드에 '참여하기'가 뜨는데 서버가 거절하는 버그가 났습니다 — 서버는 상속 권한(`grantedAccess`)을, 목록은 직접 참여(`ownGrant`)를 보고 있었습니다. `npm run check:join`이 전 사용자 × 전 프로젝트를 대조합니다.
- 새 화면(코멘트 모아보기 등)이 "볼 수 있는 범위"를 정할 때는 **기존 목록 규칙을 재사용**합니다. 규칙을 두 벌 두면 언젠가 어긋납니다.
- 조회 전용(VIEWER) 역할은 하위 트리로 상속되고, 직접 참여할 때도 등급이 유지되어야 합니다(스스로 참여하면서 일반 참여자로 올라가면 안 됨).

## 6. 알림

- 알림이 어느 화면으로 가는지는 **`lib/notify.ts`의 `notificationHrefs()` 한 곳**이 정합니다. 벨과 푸시가 같은 규칙을 씁니다.
- 새 알림 종류를 추가하면 `PARTNER_REF_TYPES` / `CALENDAR_REF_TYPES` 분류에 넣고 **`npm run check:notify`**를 돌립니다. 저장된 알림이 전부 이동 가능한지 실제로 검사합니다.
- 푸시는 알림을 만든 뒤 `pushNotifications()`를 부릅니다(내부에서 `after()`). 알림 생성 자체를 한 함수로 묶지 않은 이유는 트랜잭션 안에서 만드는 곳이 있기 때문입니다.
- 본인 행동으로 본인에게 알림이 가지 않게, 같은 사건으로 알림이 두 번 가지 않게(채팅 멘션 ↔ 채팅 알림) 확인합니다.
- **기한 알림(OVERDUE·DUE_SOON)과 캘린더 D-1 알림은 크론에서만 만들어지고, 오래된 알림 정리와 보관함 자동 비우기도 크론이 합니다.** 크론이 멈추면 이것들이 전부 멈춥니다. `CRON_SECRET`을 바꿀 때는 Vercel 값도 함께 바꾸고, Vercel 로그에서 `/api/cron/deadlines`가 200인지 확인합니다.
- 크론은 Vercel Hobby 제한상 **하루 1회, 최대 2개**입니다(지금 1개 사용). 로컬에서 크론 경로를 실제 키로 호출하면 공유 DB에서 점검이 돌고 **팀원에게 실제 푸시가 나갑니다.**

## 7. UI

- 디자인 규칙은 [`DESIGN.md`](../DESIGN.md)에 있습니다. 아이콘은 **`@tabler/icons-react`만** 씁니다.
- 한국어 긴 글: `break-keep`만으로는 띄어쓰기 없는 상호·긴 주소가 상자를 밀고 나갑니다. **`[overflow-wrap:anywhere]`를 함께** 씁니다. 줄 수 제한은 `line-clamp-*`.
- 폰트를 바꿀 때는 **한글 대체 폰트 체인을 반드시 유지**합니다(두 번 깨졌음).
- 만들기 버튼은 공용 `CreateButton`을 쓰고, 대상 목록 바로 위에 둡니다.
- 페이지 상단은 공용 `AppHeader`를 씁니다(왼쪽 로고 메뉴, 오른쪽 동작 + 알림 종).
- 보기 상태는 URL에 담습니다. 계정별로 기억할 값은 `lib/view-prefs-config.ts`의 `REMEMBERED_PARAMS`에 등록합니다. **주소에 적힌 값이 항상 우선**입니다.
- 키보드 단축키를 추가할 때는 입력 중·조합키·대화창이 떠 있을 때를 제외합니다(`components/bottom-nav.tsx` 참고).

## 8. 검증

- 로직을 추가하면 **실패하면 바로 드러나는 검사 하나**를 `scripts/check-*.ts`로 남기고 `package.json`에 `check:*`로 등록합니다. 버그를 고쳤다면, 고치기 전 코드로 돌렸을 때 실패하는지까지 확인합니다.
- 화면 변경은 브라우저에서 실제로 조작해 확인합니다. 콘솔·로그 버퍼에는 이미 고친 오류가 남아 있을 수 있으니 **지금 DOM과 서버 HTML**로 판단합니다.
- 커밋 전: `npx tsc --noEmit`, `npx eslint`, `npx next build`, 관련 `check:*`.
- **CI**(`.github/workflows/ci.yml`)가 푸시마다 같은 것을 빈 환경에서 돌린다. 새 순수 검사(DB 없음)를 만들면 CI 목록에도 넣는다. DB 검사는 넣지 않는다(운영 DB).
- 빈 환경에서는 `npx next typegen`을 먼저 돌려야 `tsc`가 `PageProps`를 찾는다.
- **되돌릴 수 없는 일괄 삭제**(자동 삭제 등)를 새로 켤 때는 지금 데이터에서 무엇이 지워질지 **삭제 없이 개수부터 센다.** 보관함 자동 비우기는 이걸 하지 않았으면 배포 다음 날 4건을 예고 없이 지웠다.
- 커밋 메시지는 **무엇을 바꿨는지보다 왜 바꿨는지**를 씁니다. 이 문서와 `HISTORY.md`가 거기서 나옵니다.
