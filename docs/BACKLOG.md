## 🟢 개선

| # | 항목 | 근거 |
|---|---|---|
| F1 | **태스크에 기한·담당자 추가** | 처음엔 단순 체크리스트였지만 태스크 탭·보드 뷰·담당자 표시까지 붙으며 독립 항목처럼 쓰이고 있다. 기한·담당자가 생기면 기존 마감 알림·캘린더·'오늘/이번주 마감'에 바로 연결된다. |
| F3 | 채팅 → Supabase Realtime | 지금은 패널이 열려 있고 탭이 보일 때만 3초 폴링이라 당장 문제는 아니다. 사용자가 늘면 그때. |
| F4 | 반복 주기 확장 | 지금은 '매주'만 있다(`Project.recurrence`). 월간 보고처럼 매월 반복이 필요해지면. |
| F5 | `User.lastDeadlineCheckAt` 컬럼 삭제 | 10-14부터 쓰지 않는다. 그 변경이 운영에 배포된 뒤 다음 마이그레이션 때 지운다(배포 전에 지우면 옛 코드가 깨진다). |
| F6 | 손으로 파트너를 영구 삭제할 때 구글 일정 정리 | `hardDeletePartner`는 그 안의 프로젝트가 구글로 내보낸 일정을 지우지 않는다(자동 삭제는 지운다). 같은 정리를 손 삭제에도 붙인다. |
| F7 | CI에 DB 검사 추가 | O1(개발 DB 분리) 뒤에. 지금은 운영 DB라 CI에서 돌리지 않는다. |

## 알려진 제약 (고치지 않기로 한 것)

| 항목 | 이유 |
|---|---|
| 날짜 칸에 연도를 6자리까지 **타이핑**할 수 있다 | 브라우저 기본 위젯 동작이라 막을 수 없다. 직접 만든 입력칸으로 바꾸면 모바일 OS 날짜 피커를 잃는다. 제출은 막혀 있다. |
| 프로젝트의 파트너를 옮겨도 참여자는 정리하지 않는다 | 새 파트너에 소속되지 않은 참여자가 남을 수 있다. 의도적으로 손대지 않았다. |
| `deepmerge-ts` 취약점 경고 3건 | Prisma 경유. 자동 수정이 Prisma 6으로 내리는 것을 요구해 적용하지 않았다. |
